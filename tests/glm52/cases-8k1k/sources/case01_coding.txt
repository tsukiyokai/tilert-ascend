Section 2: Coordinate Geometry, Work Area Partitioning, and Window Manager State Machine

Let W denote the current viewport width and H denote the current viewport height in CSS pixels, dynamically updated whenever the browser window resizes.

2.2 Window Descriptor Record and Z-Order Invariants
Each window instance maintains a unique monotonically increasing numeric identifier, an application type key, a human-readable title, current floating geometry (x, y, width, height), saved pre-maximize geometry (savedX, savedY, savedWidth, savedHeight), minimum size constraints (minWidth = 340, minHeight = 240 unless overridden per app), lifecycle state (normal, minimized, maximized, closing), minimize animation progress parameter t in [0, 1], snap-zone state (none, left-half, right-half), dirty/redraw flags, and an application controller instance implementing mount, resize, focus, blur, keydown, keyup, update, and destroy lifecycle hooks.
The Window Manager maintains an ordered list of active window identifiers representing strict back-to-front painter's z-order. Exactly one non-minimized window—the last non-minimized element in the z-order array—holds keyboard focus at any moment. Clicking anywhere inside an unfocused window's frame or client area immediately promotes that window to the top of the z-order before dispatching the pointer event to its client controls, updates the Top Menu Bar's active application label, triggers the previous foreground window's blur hook, and triggers the newly promoted window's focus hook.
If the currently focused window is minimized or closed, focus automatically transfers to the next highest non-minimized window in z-order; if none remain, focus transfers to the Desktop shell itself.

2.3 Pointer Interaction Modes: Dragging, Snapping, and Eight-Way Resizing
Pointer capture semantics must prevent fast mouse movement from losing track of an active drag or resize gesture even when the cursor travels outside the window's DOM or canvas bounds.
Each normal (non-maximized) window exposes an invisible 6-pixel resize border halo around its four edges (north, south, east, west) and 12-by-12-pixel corner zones (northwest, northeast, southwest, southeast), updating the cursor style appropriately to ns-resize, ew-resize, nwse-resize, or nesw-resize on hover.
During a resize gesture:
Resizing from the east edge updates width = max(minWidth, startWidth + dx).
Resizing from the south edge updates height = max(minHeight, startHeight + dy).
Resizing from the west edge computes candidateWidth = startWidth - dx; if candidateWidth >= minWidth, width becomes candidateWidth and x becomes startX + dx; otherwise width locks at minWidth and x locks at startX + (startWidth - minWidth) so the right edge never drifts!
Resizing from the north edge computes candidateHeight = startHeight - dy and clamps y >= 28 as well as candidateHeight >= minHeight so neither the south edge drifts nor the titlebar crosses into the Top Menu Bar.
Corner gestures compose the corresponding horizontal and vertical edge rules atomically. Whenever width or height changes, the hosted application's resize hook receives the exact inner client dimensions.

During a titlebar drag gesture (initiated on mouse down or pointer down over the 32-pixel-tall window header outside the three traffic-light buttons):
If the window is currently in maximized or half-snapped state and the pointer moves more than 6 pixels from the initial press point, the window smoothly un-maximizes back to its saved floating width and height while anchoring the titlebar horizontally at the proportional cursor ratio so the window stays naturally under the user's cursor.
While dragging near the left viewport boundary (pointer x <= 14 pixels), a translucent rounded snap-preview phantom rectangle highlights the left half of the Maximized Work Area (x = 6, y = 34, width = W/2 - 9, height = H - 116). Dragging near the right viewport boundary (pointer x >= W - 14 pixels) highlights the right half of the Maximized Work Area. Dragging against the top Menu Bar boundary (pointer y <= 32 pixels) highlights the full Maximized Work Area. Releasing the pointer while a snap-preview phantom is active commits the window geometry to that snapped region while preserving saved floating coordinates for subsequent un-snapping.
Double-clicking the titlebar toggles cleanly between maximized work-area geometry and saved floating geometry.

2.4 Minimize and Restore Kinematics

4.2 Input Buffering and Anti-Self-Reversal Queue
A common flaw in naive Snake implementations occurs when a player presses two perpendicular direction keys rapidly within a single simulation tick (for example, moving Right, pressing Up and then Left within 40 milliseconds), causing an immediate illegal 180-degree self-collision before the Up step executes. To eliminate this defect completely, implement a bounded two-slot FIFO direction input queue: each incoming arrow or WASD key press compares against the last queued direction (or the snake's current heading if the queue is empty) and enqueues the new cardinal vector only if it is neither identical nor opposite to that reference vector! Only the focused foreground Cyber-Snake window processes directional keyboard input; if focus moves to Terminal or another window, Cyber-Snake automatically engages a translucent Pause overlay (or continues running smoothly if Autopilot Demo Mode is active).

4.4 Autonomous AI Pathfinding Algorithm (BFS + Virtual Survival Check)
The built-in AI Autopilot must never trap itself carelessly in obvious cavities:
At each tick when Autopilot is active, construct a virtual occupancy grid of the snake body (noting that the tail tip cell vacates on the next tick unless growth is pending).
Step 1: Run Breadth-First Search from the snake's head to the primary target fruit to find a shortest valid path P.
Step 2: Simulate advancing a virtual copy of the snake along path P until it consumes the fruit, then run a second reachability check from the virtual head to the virtual tail tip! If the virtual tail remains reachable after eating the fruit, commit the first step of P immediately.
Step 3: If eating the fruit along P would seal the snake inside a pocket disconnected from its own tail, discard P and instead select among all immediately safe neighbor moves the move that maximizes Manhattan distance toward the fruit while preserving reachability to the current tail tip (longest-safe-chase heuristic). If even tail reachability is impossible, pick the neighbor whose flood-filled connected component of free cells has maximum area so the snake survives as long as mathematically possible.

Section 12: Exact Collision Impulse, Spring Tearing, and Numerical Stability Specification
12.1 Rigid Orb Elastic Collision Mathematics in Vector Physics Studio
To guarantee unconditional numerical stability even when dozens of rigid orbs pile onto barriers or collide simultaneously inside a resized small window:
Sub-step each physics frame into four deterministic sub-iterations of dt_sub = (1 / 240) second.
For every pair of dynamic orbs i and j with centers p_i, p_j, velocities v_i, v_j, radii r_i, r_j, and masses m_i, m_j proportional to r^2:
Compute separation vector n_raw = p_j - p_i and Euclidean distance d = length(n_raw). If d < r_i + r_j and d > 1e-6:
First perform positional penetration correction (Baumgarte / projection separation) pushing p_i and p_j apart along unit normal n = n_raw / d inversely proportional to their masses so overlap penetration (r_i + r_j - d) resolves immediately without energy injection!
Second compute relative velocity along normal v_rel = dot(v_j - v_i, n). Only if v_rel < 0 (approaching), apply scalar impulse j_imp = -(1 + restitution) * v_rel / (1/m_i + 1/m_j) with default coefficient of restitution 0.78, updating v_i -= (j_imp / m_i) * n and v_j += (j_imp / m_j) * n.
For orb-against-segment barrier collisions with barrier endpoints A and B: compute clamped projection parameter t_seg = clamp(dot(p_i - A, B - A) / dot(B - A, B - A), 0, 1) and closest point Q = A + t_seg * (B - A). If length(p_i - Q) < r_i + barrierHalfThickness, project p_i outside the capsule surface along unit normal (p_i - Q) / length(p_i - Q) and reflect normal velocity component with restitution 0.82 and tangential surface friction factor 0.98.

12.2 Verlet Cloth Integration and Dynamic Tear Thresholds
Represent cloth particles by current position x_k, previous position x_prev_k, pinned boolean flag, and mass.
